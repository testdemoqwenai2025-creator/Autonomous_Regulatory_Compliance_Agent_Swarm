     1→     1→# Maritime Global Compliance Swarm
     2→     2→
     3→     3→> Autonomous regulatory compliance agent swarm for global maritime freight. Automates GDPR/PII anonymisation, EDI compliance audits, remediation policy generation, MTTR telemetry, finding state machine governance, and event-driven reactive compliance — all exposed via a unified Python FastAPI gateway with an interactive HTML dashboard.

     7→     7→## Functioning Preview Endpoint
     8→     8→
     9→     9→The live frontend-backend communication can be verified at any time via the **Frontend Status** endpoint. This is the single endpoint that confirms the frontend can reach every backend component and proves end-to-end event flow:
    10→    10→
    11→    11→```bash
    12→    12→curl -s http://localhost:8000/api/v1/system/frontend-status | python3 -m json.tool
    13→    13→```
    14→    14→
    15→    15→**What it tests (10 components):**
    16→    16→
    17→    17→| # | Component | Test Performed | Expected Status |
    18→    18→|---|-----------|---------------|----------------|
    19→    19→| 1 | **Database** | `SELECT 1` read/write probe | `ok` |
    20→    20→| 2 | **State Machine** | Load full definition (10 states, 20+ transitions), callback bridge active | `ok` |
    21→    21→| 3 | **Event Bus** | Retrieve statistics — transport type, event count, subscriber count | `ok` or `degraded` |
    22→    22→| 4 | **Reaction Engine** | Retrieve statistics — active rules count, actions fired | `ok` |
    23→    23→| 5 | **Anonymiser** | Execute HMAC-SHA256 tokenisation probe | `ok` |
    24→    24→| 6 | **NER Detector** | Query spaCy availability and layer count | `ok` |
    25→    25→| 7 | **EDI Auditor** | Execute rule engine match probe | `ok` |
    26→    26→| 8 | **Remediation** | Load decision matrix (7 remediation routes) | `ok` |
    27→    27→| 9 | **MTTR Tracker (Go)** | HTTP GET to Golang service health endpoint | `ok` or `unavailable` (expected in dev without Go) |
    28→    28→| 10 | **Event Flow** | Publish a real `SYSTEM_HEALTH_CHANGED` event, process through subscriber pipeline | `ok` |

   158→   158→The FastAPI gateway exposes all tools plus the state machine, event bus, reactions, composite scoring, and knowledge graph under a unified REST API. Interactive documentation is available at `/docs` (Swagger) and `/redoc` (ReDoc) when the gateway is running.

   277→   277→## Frontend Integration Layer
   278→   278→
   279→   279→The FastAPI gateway at port 8000 is the **sole integration point** for any frontend, middleware, or external consumer. The **Frontend Status endpoint** (`GET /api/v1/system/frontend-status`) is the primary way to verify that the frontend can communicate with every backend component.
   280→   280→
   281→   281→```
   282→   282→Frontend / Middleware / External System
   283→   283→        │
   284→   284→        │  HTTP/REST (JSON)
   285→   285→        ▼
   286→   286→┌──────────────────────────────────────┐
   287→   287→│   FastAPI Gateway  (port 8000)        │
   288→   288→│   ┌──────────────────────────────┐   │
   289→   289→│   │ Middleware Pipeline           │   │
   290→   290→│   │  • Auth (JWT / API key)      │   │
   291→   291→│   │  • Rate Limiting (token bucket)│  │
   292→   292→│   │  • Request Validation         │   │
   293→   293→│   │  • Structured Audit Logging   │   │
   294→   294→│   └──────────┬───────────────────┘   │
   295→   295→│              │                       │
   296→   296→│    ┌─────────┼─────────┐             │
   297→   297→│    ▼         ▼         ▼             │
   298→   298→│ Anonymiser  Auditor  Remediation     │
   299→   299→│ (Python)    (Python) (Python)        │
   300→   300→│              │                       │
   301→   301→│              ▼                       │
   302→   302→│         MTTR Tracker (Go:8080)       │
   303→   303→│         via httpx proxy              │
   304→   304→└──────────────────────────────────────┘
   305→   305→```

   307→   307→### Integration Patterns
   308→   308→
   309→   309→| Pattern | How | Use Case |
   310→   310→|---------|-----|----------|
   311→   311→| **Frontend Status** | `GET /api/v1/system/frontend-status` | **Primary integration check** — call this first from any frontend to confirm all 10 backend services are reachable + end-to-end event flow proof |
   312→   312→| **Direct REST** | Frontend calls `GET/POST /api/v1/*` | Dashboard data, user actions |
   313→   313→| **Python SDK** | `from client import ComplianceSwarmClient` | Backend-to-backend, scripting |
   314→   314→| **MTTR Proxy** | Gateway proxies `/api/v1/mttr/*` → `Go:8080` | Transparent language boundary |
   315→   315→| **CORS** | `Access-Control-Allow-Origin` configurable | SPA, mobile apps |
   316→   316→| **OpenAPI** | Auto-generated at `/docs` | API exploration, codegen |
   317→   317→| **Connectivity Check** | `GET /api/v1/system/connectivity` | Verbose per-component health (latency, detail) |
   318→   318→| **SM→EventBus bridge** | Auto-emit callback on every transition | State changes trigger reaction rules immediately |
   319→   319→| **SM→Go MTTR bridge** | Async HTTP POST on every transition | Telemetry stays in sync across Python and Go |

   505→   505→## Operational Workflow
   506→   506→
   507→   507→See `docs/workflow_diagram.mmd` (Mermaid) or `docs/workflow_diagram.png` (rendered).
   508→   508→
   509→   509→The swarm operates in 10 phases:
   510→   510→
   511→   511→1. **Ingestion** — Raw manifests from FMS/EDI/satellite/IoT streams
   512→   512→2. **Detection** — PII rule engine + ML NER classifies fields by jurisdiction
   513→   513→3. **Tokenisation** — HMAC-SHA256 vault replaces PII with deterministic tokens
   514→   514→4. **Audit** — 11 SQL queries detect encryption, customs, and EDI violations
   515→   515→5. **Risk Scoring** — 5-dimensional composite risk scoring (severity, jurisdiction, sensitivity, exposure, urgency)
   516→   516→6. **State Machine Governance** — Finding lifecycle managed through 10 validated states with guard conditions, timeout SLAs, and dual-emit callback (EventBus + Go MTTR)
   517→   517→7. **Event-Driven Reactions** — 7 autonomous rules react to findings (CRITICAL alerts, PII auto-scan, cert checks, timeout escalation)
   518→   518→8. **Remediation** — Decision matrix auto-generates masking policies and EDI fixes
   519→   519→9. **Telemetry** — Golang service tracks MTTR across all findings, synced via SM bridge
   520→   520→10. **Observability** — Structured JSON logs, health aggregation, metrics collection, middleware audit trail
   521→   521→
   522→   522→### Finding State Machine
   523→   523→
   524→   524→Every compliance finding follows a validated lifecycle:
   525→   525→
   526→   526→```
   527→   527→DETECTED → TRIAGED → ASSIGNED → IN_REMEDIATION → AWAITING_VERIFICATION → VERIFIED → CLOSED
   528→   528→    │          │           │              │                    │                    │
   529→   529→    │          └── FALSE_POSITIVE     │              │                    └── IN_REMEDIATION (regression)
   530→   530→    │                              └── ESCALATED ←───┘                    │
   531→   531→    │                                  │                                    │
   532→   532→    └────────────────────────── RISK_ACCEPTED ────────────────────── CLOSED
   533→   533→```
   534→   534→
   535→   535→**Key features:**
   536→   536→- **Guard conditions**: CRITICAL findings cannot transition to RISK_ACCEPTED without sign-off
   537→   537→- **Timeout rules**: CRITICAL = 1hr per state, HIGH = 4hr, MEDIUM = 24hr (configurable per state)
   538→   538→- **Auto-escalation**: Timeout breaches automatically transition to ESCALATED via timer actor
   539→   539→- **Audit trail**: Every transition recorded in `finding_transitions` table with trigger, actor, context
   540→   540→- **Dual-emit callback**: Every successful transition publishes to event bus AND forwards to Go MTTR tracker
   541→   541→- **Legacy bridge**: Maps old 5-state `AuditStatus` to new 10-state `FindingState` for backward compatibility
   542→   542→
   543→   543→### Event-Driven Reactions
   544→   544→
   545→   545→The swarm reacts autonomously to compliance events through 7 built-in rules:
   546→   546→
   547→   547→| Rule | Event | Action |
   548→   548→|------|-------|--------|
   549→   549→| Critical Notification | `finding.created` (CRITICAL) | Emit high-priority alert for immediate assignment |
   550→   550→| PII Auto-Scan | `finding.created` (PII_EXPOSURE) | Queue related manifests for anonymisation scan |
   551→   551→| Cert Renewal Check | `finding.created` (CERT_EXPIRY) | Schedule 24hr cert renewal check |
   552→   552→| Timeout Escalation | `finding.timeout_breach` | Auto-escalate via state machine |
   553→   553→| Verification Reminder | `finding.state_changed` → awaiting_verification | Emit reminder with timeout window |
   554→   554→| Audit Summary | `audit.completed` | Log severity breakdown |
   555→   555→| MTTR Baseline | `finding.created` (CRITICAL/HIGH) | Create MTTR tracking baseline |

   594→   594→## Security Considerations
   595→   595→
   596→   596→- **HMAC key** — drives all tokenisation determinism; rotating it invalidates every token. Treat as a root CA key.
   597→   597→- **Fernet keys** — generated per-session by default; for production, rotate via a key management service.
   598→   598→- **Gateway auth** — JWT/API key middleware available in middleware pipeline (disabled in dev, enable in prod).
   599→   599→- **CORS** — currently wildcard; lock to your frontend domain in production.
   600→   600→- **Rate limiting** — token-bucket middleware available (100 req/min default, configurable).
   601→   601→- **Audit logging** — structured audit log middleware captures every request with request ID, timestamp, and response status.
