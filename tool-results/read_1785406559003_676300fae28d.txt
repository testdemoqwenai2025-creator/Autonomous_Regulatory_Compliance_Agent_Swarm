     1→# Maritime Global Compliance Swarm
     2→
     3→> **v3.1** — Autonomous regulatory compliance agent swarm for global maritime freight. Automates GDPR/PII anonymisation, EDI compliance audits, remediation policy generation, MTTR telemetry, finding state machine governance, and event-driven reactive compliance — all exposed via a unified Python FastAPI gateway with an interactive HTML dashboard.

     7→## Functioning Preview Endpoint
     8→
     9→> **This section is permanent.** It proves frontend-backend and all component communication progress. It MUST always feature in this README for every version going forward.
    10→
    11→The live frontend-backend communication can be verified at any time via the **Frontend Status** endpoint. This is the single endpoint that confirms the frontend can reach every backend component and proves end-to-end event flow:
    12→
    13→```bash
    14→curl -s http://localhost:8000/api/v1/system/frontend-status | python3 -m json.tool
    15→```
    16→
    17→**What it tests (10 components):**
    18→
    19→| # | Component | Test Performed | Expected Status |
    20→|---|-----------|---------------|----------------|
    21→| 1 | **Database** | `SELECT 1` read/write probe | `ok` |
    22→| 2 | **State Machine** | Load full definition (10 states, 20+ transitions), callback bridge active | `ok` |
    23→| 3 | **Event Bus** | Retrieve statistics — transport type, event count, subscriber count | `ok` or `degraded` |
    24→| 4 | **Reaction Engine** | Retrieve statistics — active rules count, actions fired | `ok` |
    25→| 5 | **Anonymiser** | Execute HMAC-SHA256 tokenisation probe | `ok` |
    26→| 6 | **NER Detector** | Query spaCy availability and layer count | `ok` |
    27→| 7 | **EDI Auditor** | Execute rule engine match probe | `ok` |
    28→| 8 | **Remediation** | Load decision matrix (7 remediation routes) | `ok` |
    29→| 9 | **MTTR Tracker (Go)** | HTTP GET to Golang service health endpoint | `ok` or `unavailable` (expected in dev without Go) |
    30→| 10 | **Event Flow** | Publish a real `SYSTEM_HEALTH_CHANGED` event, process through subscriber pipeline | `ok` |

   158→## API Reference (45 routes)
   159→
   160→The FastAPI gateway exposes all tools plus the state machine, event bus, reactions, composite scoring, and knowledge graph under a unified REST API. Interactive documentation is available at `/docs` (Swagger) and `/redoc` (ReDoc) when the gateway is running.
   161→
   162→### Health & Frontend Status
   163→
   164→| Method | Path | Description |
   165→|--------|------|-------------|
   166→| GET | `/health` | Liveness probe — status of all tools |
   167→| GET | `/api/v1/system/frontend-status` | **Frontend status endpoint** — lightweight confirmation that the UI can reach every backend component, including an end-to-end event flow proof. Call this first from any frontend to confirm backend communication. |
   168→| GET | `/api/v1/system/connectivity` | Full connectivity diagnostics (10 components, per-component latency ms, verbose detail) |
   169→
   170→### 1. PII Anonymiser
   171→
   172→| Method | Path | Description |
   173→|--------|------|-------------|
   174→| POST | `/api/v1/anonymise/manifest` | Tokenise all PII fields in a shipping manifest |
   175→| POST | `/api/v1/anonymise/free-text` | Detect and tokenise PII in free-text content |
   176→| POST | `/api/v1/anonymise/scan` | Scan a manifest for PII without modifying data |
   177→| POST | `/api/v1/anonymise/ner/scan` | ML NER detection (spaCy) for free-text PII |
   178→| POST | `/api/v1/anonymise/ner/anonymise` | ML NER + anonymise in one step |
   179→
   180→**Example — Scan a manifest:**
   181→```bash
   182→curl -X POST http://localhost:8000/api/v1/anonymise/scan \
   183→  -H 'Content-Type: application/json' \
   184→  -d '{"manifest": {"consignee_name": "John Doe", "consignee_email": "john@ship.com"}}'
   185→```
   186→
   187→**Example — Anonymise:**
   188→```bash
   189→curl -X POST http://localhost:8000/api/v1/anonymise/manifest \

   192→    "manifest_id": "BL-SG-001",
   193→    "manifest": {
   194→      "consignee_name": "John Doe",

   279→## Frontend Integration Layer
   280→
   281→The FastAPI gateway at port 8000 is the **sole integration point** for any frontend, middleware, or external consumer. The **Frontend Status endpoint** (`GET /api/v1/system/frontend-status`) is the primary way to verify that the frontend can communicate with every backend component.
   282→
   283→```
   284→Frontend / Middleware / External System
   285→        │
   286→        │  HTTP/REST (JSON)
   287→        ▼
   288→┌──────────────────────────────────────┐
   289→│   FastAPI Gateway  (port 8000)        │
   290→│   ┌──────────────────────────────┐   │
   291→│   │ Middleware Pipeline           │   │
   292→│   │  • Auth (JWT / API key)      │   │
   293→│   │  • Rate Limiting (token bucket)│  │
   294→│   │  • Request Validation         │   │
   295→│   │  • Structured Audit Logging   │   │
   296→│   └──────────┬───────────────────┘   │
   297→│              │                       │
   298→│    ┌─────────┼─────────┐             │
   299→│    ▼         ▼         ▼             │
   300→│ Anonymiser  Auditor  Remediation     │
   301→│ (Python)    (Python) (Python)        │
   302→│              │                       │
   303→│              ▼                       │
   304→│         MTTR Tracker (Go:8080)       │
   305→│         via httpx proxy              │
   306→└──────────────────────────────────────┘
   307→```
   308→
   309→### Integration Patterns
   310→
   311→| Pattern | How | Use Case |
   312→|---------|-----|----------|
   313→| **Frontend Status** | `GET /api/v1/system/frontend-status` | **Primary integration check** — call this first from any frontend to confirm all 10 backend services are reachable + end-to-end event flow proof |
   314→| **Direct REST** | Frontend calls `GET/POST /api/v1/*` | Dashboard data, user actions |
   315→| **Python SDK** | `from client import ComplianceSwarmClient` | Backend-to-backend, scripting |
   316→| **MTTR Proxy** | Gateway proxies `/api/v1/mttr/*` → `Go:8080` | Transparent language boundary |
   317→| **CORS** | `Access-Control-Allow-Origin` configurable | SPA, mobile apps |
   318→| **OpenAPI** | Auto-generated at `/docs` | API exploration, codegen |
   319→| **Connectivity Check** | `GET /api/v1/system/connectivity` | Verbose per-component health (latency, detail) |
   320→| **SM→EventBus bridge** | Auto-emit callback on every transition | State changes trigger reaction rules immediately |
   321→| **SM→Go MTTR bridge** | Async HTTP POST on every transition | Telemetry stays in sync across Python and Go |

   344→## Python Client SDK
   345→
   346→A typed client is included for frontend and integration use:
   347→
   348→```python
   349→from client import ComplianceSwarmClient, ComplianceDomain, RemediationMode
   350→
   351→api = ComplianceSwarmClient(base_url="http://localhost:8000")
   352→
   353→# Verify frontend-backend communication
   354→status = api.get_frontend_status()
   355→print(f"System status: {status['status']}")
   356→for name, svc in status['services'].items():
   357→    print(f"  {name}: {svc['status']}")
   358→
   359→# Scan a manifest for PII
   360→scan = api.scan_manifest({"consignee_name": "John Doe", "consignee_email": "john@ship.com"})
   361→print(f"Found {scan.pii_fields_found} PII fields")
   362→
   363→# Anonymise
   364→result = api.anonymise_manifest(
   365→    manifest_id="BL-SG-001",
   366→    manifest={"consignee_name": "John Doe", "container_id": "MSKU123"},
   367→)
   368→print(result.anonymised_manifest)  # PII replaced with MTS_CONS_xxxx tokens
   369→
   370→# Run an audit
   371→audit = api.run_audit(domain=ComplianceDomain.ENCRYPTION)
   372→print(f"{audit.findings_count} findings from {audit.queries_executed} queries")
   373→
   374→# Generate remediation policies (dry-run)
   375→policies = api.generate_policies(mode=RemediationMode.DRY_RUN)
   376→
   377→# MTTR report
   378→report = api.get_mttr_report()
   379→print(f"Avg MTTR: {report.avg_mttr_hours}h, P95: {report.p95_mttr_hours}h")
   380→
   381→api.close()
   382→```

   507→## Operational Workflow
   508→
   509→See `docs/workflow_diagram.mmd` (Mermaid) or `docs/workflow_diagram.png` (rendered).
   510→
   511→The swarm operates in 10 phases:
   512→
   513→1. **Ingestion** — Raw manifests from FMS/EDI/satellite/IoT streams
   514→2. **Detection** — PII rule engine + ML NER classifies fields by jurisdiction
   515→3. **Tokenisation** — HMAC-SHA256 vault replaces PII with deterministic tokens
   516→4. **Audit** — 11 SQL queries detect encryption, customs, and EDI violations
   517→5. **Risk Scoring** — 5-dimensional composite risk scoring (severity, jurisdiction, sensitivity, exposure, urgency)
   518→6. **State Machine Governance** — Finding lifecycle managed through 10 validated states with guard conditions, timeout SLAs, and dual-emit callback (EventBus + Go MTTR)
   519→7. **Event-Driven Reactions** — 7 autonomous rules react to findings (CRITICAL alerts, PII auto-scan, cert checks, timeout escalation)
   520→8. **Remediation** — Decision matrix auto-generates masking policies and EDI fixes
   521→9. **Telemetry** — Golang service tracks MTTR across all findings, synced via SM bridge
   522→10. **Observability** — Structured JSON logs, health aggregation, metrics collection, middleware audit trail
   523→
   524→### Finding State Machine
   525→
   526→Every compliance finding follows a validated lifecycle:
   527→
   528→```
   529→DETECTED → TRIAGED → ASSIGNED → IN_REMEDIATION → AWAITING_VERIFICATION → VERIFIED → CLOSED
   530→    │          │           │              │                    │                    │
   531→    │          └── FALSE_POSITIVE     │              │                    └── IN_REMEDIATION (regression)
   532→    │                              └── ESCALATED ←───┘                    │
   533→    │                                  │                                    │
   534→    └────────────────────────── RISK_ACCEPTED ────────────────────── CLOSED
   535→```
   536→
   537→**Key features:**
   538→- **Guard conditions**: CRITICAL findings cannot transition to RISK_ACCEPTED without sign-off
   539→- **Timeout rules**: CRITICAL = 1hr per state, HIGH = 4hr, MEDIUM = 24hr (configurable per state)
   540→- **Auto-escalation**: Timeout breaches automatically transition to ESCALATED via timer actor
   541→- **Audit trail**: Every transition recorded in `finding_transitions` table with trigger, actor, context
   542→- **Dual-emit callback**: Every successful transition publishes to event bus AND forwards to Go MTTR tracker
   543→- **Legacy bridge**: Maps old 5-state `AuditStatus` to new 10-state `FindingState` for backward compatibility
   544→
   545→### Event-Driven Reactions
   546→
   547→The swarm reacts autonomously to compliance events through 7 built-in rules:
   548→
   549→| Rule | Event | Action |
   550→|------|-------|--------|
   551→| Critical Notification | `finding.created` (CRITICAL) | Emit high-priority alert for immediate assignment |
   552→| PII Auto-Scan | `finding.created` (PII_EXPOSURE) | Queue related manifests for anonymisation scan |
   553→| Cert Renewal Check | `finding.created` (CERT_EXPIRY) | Schedule 24hr cert renewal check |
   554→| Timeout Escalation | `finding.timeout_breach` | Auto-escalate via state machine |
   555→| Verification Reminder | `finding.state_changed` → awaiting_verification | Emit reminder with timeout window |
   556→| Audit Summary | `audit.completed` | Log severity breakdown |
   557→| MTTR Baseline | `finding.created` (CRITICAL/HIGH) | Create MTTR tracking baseline |

   596→## Security Considerations
   597→
   598→- **HMAC key** — drives all tokenisation determinism; rotating it invalidates every token. Treat as a root CA key.
   599→- **Fernet keys** — generated per-session by default; for production, rotate via a key management service.
   600→- **Gateway auth** — JWT/API key middleware available in middleware pipeline (disabled in dev, enable in prod).
   601→- **CORS** — currently wildcard; lock to your frontend domain in production.
   602→- **Rate limiting** — token-bucket middleware available (100 req/min default, configurable).
   603→- **Audit logging** — structured audit log middleware captures every request with request ID, timestamp, and response status.
